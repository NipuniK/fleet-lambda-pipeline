1. The Speed Layer

Consumes continuous vehicle telemetry from Kafka. It uses Spark Structured Streaming to perform windowed aggregations, calculating real-time fleet utilization, idle ratios, and active vehicle counts with extremely low latency.

Apache Kafka PySpark Streaming
🕰️

2. The Batch Layer

Runs once per simulated day. It joins the day's aggregated telemetry with static daily cost files to generate an auditable vehicle profitability report. Orchestrated completely by Apache Airflow to ensure consistency.

Apache Airflow PySpark Batch
🧠

3. Why Lambda over Kappa?

Correctness & Cost. Live utilization needs fast, approximate answers (Speed Layer). Profitability needs exact answers computed over bounded 24hr cost drops (Batch Layer). Lambda allows both queries to thrive without slowing down streaming for batch accuracy.

Architecture Decision Trade-offs
👁️

4. Serving & Observability

The layers converge on PostgreSQL. A dedicated Alert Watcher constantly monitors for stuck vehicles and missing data streams, instantly pushing alerts to FastAPI, alongside a fully structured JSON logging suite.
